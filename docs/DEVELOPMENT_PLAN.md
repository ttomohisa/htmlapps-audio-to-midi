## 1. 開発思想

**録音→音符抽出→聴き比べ→最低限の修正→MIDI保存**を、端末内で一度の作業として完了させる。

- 機械学習モデルの「採譜精度」だけを品質としない。解析の失敗や誤検出があってもユーザーが最終成果物を作れることを優先する。
- 各バージョンは**その時点で実際に動き、前バージョンの機能を壊さない**状態で区切る。
- 単一HTML、`file://`、CSP、ローカル処理、日英UI、スマホ操作は最終盤まで後回しにしない。特に技術の成立性はv0.1.0で先に解決する。
- 基本の推論経路はSpotifyのTypeScript/TF.js版を技術検証し、**精度・メモリ・配布サイズ・CSPの総合評価**で採否を決める。ONNX/TFLiteへの切り替えは手段であってマイルストーンではない。
- 各PRはユーザーがレビュー・マージする。作業者はマージしない。

## 2. 優先順位と採否ルール

| 区分 | 意味 | 例 |
|---|---|---|
| **Must** | 欠けると本来の用途を達成できない | ファイル解析、MIDI保存、ノート確認・修正、無通信、Undo、スマホUI |
| **Should** | 明確に利便性を改善する | 録音、感度選択、ノート結合・分割、CSV |
| **Conditional** | 検証で効果・互換性が確認された場合だけ正式搭載 | 長時間5分対応、ピッチベンド |
| **Future** | v1.0.0を延期してまで追加しない | 五線譜、音源分離、複数トラック、楽器音源ライブラリ |

条件付き機能が通らなくても**必須動線と正確な制限表示**が満たされていればv1.0.0をリリースしてよい。

## 3. 初動: 技術検証・リポジトリ準備（v0.1.0の開始作業に含む）

### 調査・準備

1. アプリの対象リポジトリが指定/作成されたら、対象の**現在の状態**を確認する。提案名は `htmlapps-audio-to-midi` だが存在するとは仮定しない。
2. 最新 `htmlapps-template` をGitHubで確認し、`AGENTS.md`、`APP_SPEC.md`、`docs/ARCHITECTURE.md`、`docs/LLM_WORKFLOW.md`、`components/`、ビルド手順を読む。
3. 商品名、説明、日英UI、ブランドカラー `#16624F`、SVGアイコン、利用モデルの帰属情報を設定する。
4. 公式TypeScript版・TF.js GraphModelを固定版で試し、`AudioBuffer`/`Float32Array`を22,050Hzモノラルへ変換するルートを決める。
5. GraphModelを埋め込まれたバイト列から読み込む方式を検証する。**CSP `connect-src 'none'`を弱めない**ことが前提。`file://`上でネットワークに頼らず初回解析できること。
6. 合成サイン波・鼻歌・単音楽器・和音・無音を収録した再配布可能な評価セットを用意し、モデル出力とMIDIパーサーを検証する。

### v0.1開始の技術ゲート

- 少なくともWindows Chrome/Edge、Android Chrome、iOS Safariで10秒の音源が解析できるか実機確認。未検証端末は未検証と記す。
- 単一HTML版で音声ファイルからノートが生成され、`.mid`がダウンロードできる。
- 推論用モデル/WASM/JSの合計サイズと主要端末の初回解析時間を測定できる。
- これらが成立しない場合は、ONNX/TFLite移植を検証して方式を選び直す。**HTTPへのモデル取得に逃げたり、無通信要件を外したりしない。**

## 4. バージョン別計画

### v0.1.0 — 音声ファイルからMIDIを作れる

**ユーザー成果:** 1つの短い音声を入れてMIDIに変換・保存できる。

**実装するもの**

- ファイル選択/D&D、WAV/MP3の対応環境内読込、長さ/容量/形式の検査。初期上限50MiB・0.5〜60秒。
- Web Audioデコード、22,050Hzモノラル変換、Basic Pitch推論、最小限のノート後処理。
- 推論中の明確な進捗、キャンセル、無音/0ノート/不正形式/長すぎる入力の案内。
- 推定ノート数・概要の表示。**ピアノロール・録音・編集はまだない**と明記。
- MIDIの正しい秒数→tick変換（既定テンポ120BPM、固定velocity96、SMFタイプ1・ノートトラック）。ファイル名編集と`.mid`ダウンロード。
- 日英UIの基本実装、`file://`対応、単一HTML通常版+自己展開版、`connect-src 'none'`、モデル/JS固定・ライセンス記載。
- 出力を別MIDIパーサーで再読込する自動テスト、合成音源による実測結果の記録。

**完了条件（DoD）**

- `ACCEPTANCE_MATRIX.md` のv0.1項目がすべて通る。
- Windowsとスマホの少なくとも1台ずつで、ファイル→解析→MIDI保存を完走。
- 無音の場合に保存ボタンは無効。失敗時も再試行でき、前の入力の結果が混入しない。
- `dist/index.html`と`dist/index.self-extract.html`の両方をローカルで開き、解析〜保存が動く。

**この段階でしないこと:** 編集、録音、音色の作り込み、完璧な精度の追求。

### v0.2.0 — 音符を見て、元音声と聴き比べられる

**ユーザー成果:** 自動推定の誤りを聴いて発見できる。

**実装するもの**

- ピアノロール（時間軸・音高軸・ノート矩形・音名）、スクロール/ズーム。
- 波形（Canvas等）と再生位置・時間目盛りの同期。元音声の再生と簡易シンセ試聴の切り替え。
- 音符を選択して音高と開始/終了時刻を表示。まだ変更は不可。
- 再生・一時停止・停止・シーク。入力を入れ替えたら音とタイムラインが更新され、旧ソースは止まる。
- スマホではピアノロール専用の横スクロール領域を用意し、画面全体の横スクロールを防ぐ。

**完了条件**

- 既知のテストノートが正しい位置に描かれ、拡大/移動しても秒数と音高は保持される。
- 元音声と試聴音のどちらを選んだか明確で、再生位置がずれない。再生終了時にリソースが残らない。
- スマホの縦画面で波形・編集対象・操作が離れず、320/360pxで横はみ出しがない。

### v0.3.0 — スマホで録音して変換できる

**ユーザー成果:** 別アプリで録音せず、鼻歌をMIDIへ変換できる。

**実装するもの**

- ユーザー操作によるマイク権限取得、録音・停止・再生・破棄、録音ファイルの保存（任意）。
- `MediaRecorder`の対応MIMEを実行時に判定し、ブラウザで再デコードできる形式だけを採用。非対応なら明確に案内する。
- ファイル入力と録音結果を**同じ解析経路**へ渡す。録音停止直後に勝手に推論を開始せず、確認して解析する。
- 録音中インジケーター、音量入力メーター（軽量）、録音中の入力切替/画面遷移時の確認。
- スマートフォン向け「読み込み / 音符 / 書き出し」タブ・安全な下部バー。マイク権限拒否時でもファイル変換を使用可能。

**完了条件**

- 許可/拒否/デバイスなし/マイク途中喪失の各状態で適切に復旧。
- 録音終了後にMediaStreamTrackが止まり、マイク入力がスピーカーへ流れない。
- HTTPSでの録音完走。`file://`で録音できないブラウザには説明と代替手段を表示。

### v0.4.0 — 音符を手動修正できる

**ユーザー成果:** AIが1音間違えても自分で修正して保存できる。

**実装するもの**

- ノート選択、追加、削除、半音上下、開始/終了の変更。音名/秒数の直接入力を用意。
- PC: マウス/キーボード、スマホ: ノート選択→近接する編集操作パネル（大きなタップ領域）。
- 編集内容をピアノロール、簡易試聴、MIDI書き出しに即反映。
- 削除にはToast+Undo。既存ノートと手動追加ノートを内部データで区別する。
- 編集結果を元解析と明確に分離する。再解析・入力変更・リセットで未保存変更がある場合は通知。

**完了条件**

- 「音程を1半音上げる」「開始を0.05秒動かす」「1音を削除する」をスマホでも確実に実施。
- `start < end`や入力長上限のバリデーションが崩れない。重なった音は合法として扱う。
- MIDI再読込時に**編集後**のノート列と一致する。Undoで削除が復元できる。

### v0.5.0 — 検出感度・音域・Undo/Redo

**ユーザー成果:** 音声に合わせて音符の出方を調整でき、修正ミスを取り消せる。

**実装するもの**

- 感度プリセット「少なめ / 標準 / 多め」。折りたたみ詳細にOnset/Frameしきい値、最短長さ、音域上下限。
- 変更した設定で再解析・後処理し直せる。ただし編集中結果を自動上書きしない。切替前に確認し、失敗時は旧結果を保持。
- Undo/Redo最大100操作。ショートカット: Ctrl/⌘+Z、Ctrl/⌘+Shift+Zなど。
- しきい値の変更に伴う極端なノート数増加を警告、音域の上下値不整合は入力欄近くで説明。
- プリセットごとのパラメータをコード/テストに固定し、UI文言の意味を一致させる。

**完了条件**

- 3プリセットで後処理結果が変わるケースを用意し、変わらない入力も正常と扱う。
- Undo/Redoの順序・100操作上限・途中の新規編集によるRedo破棄をテスト。
- 未保存編集が再解析により消える経路は確認なしで通らない。

### v0.6.0 — 出力音符の整理

**ユーザー成果:** 細かく分かれた音符や長さのばらつきを短時間で整えられる。

**実装するもの**

- 選択ノートの分割、同一音高の隣接ノートの結合。
- 短い誤検出ノートの削除を提案。まとめて変更する前に対象件数と結果を表示し、Undo可能。
- クオンタイズ/開始・終了時刻のグリッド補正を任意設定として追加。既定OFF、未推定テンポを自動指定しない。
- 弱い検出への説明（「余計なノートが増える可能性」）を改善。

**完了条件**

- 結合は音高と時間条件に合うノートに限る。異なる音高の結合を無効化。
- 分割後2ノートの合計範囲は分割前と一致。補正前の状態をUndoで復帰できる。
- 初期状態でグリッド補正を行わず、音符の自然な揺らぎを保持する。

### v0.7.0 — 大きい音声とメモリの最適化

**ユーザー成果:** スマホでも安定し、処理中に画面が固まらない。

**実装するもの**

- 10/30/60秒と端末別の処理時間・ピークメモリ測定。モデルはセッション内で再利用。
- Worker/非同期処理を導入または改善し、進捗・キャンセル・古い世代の結果廃棄を検証。
- 波形とピアノロールを可視範囲描画、データ解放（Tensor.dispose、AudioBuffer、BlobURL等）を徹底。
- 解析ウィンドウ境界の重複ノート・欠落・タイムスタンプずれを検証し、**条件が通れば**初期の60秒上限を最大5分候補まで拡大する。
- `decodeAudioData()`は完結した圧縮ファイル単位でしか扱えないことを踏まえ、長時間入力時のデコード方式を別途評価する。

**完了条件**

- 100回の短時間解析/中断ループでセッションが破綻しない。
- 入力変更の連打、解析キャンセル、ブラウザバックグラウンド化などで古い結果が再表示されない。
- 時間上限引上げは**Android/iOSの実機とPCで検証合格した場合のみ**。未合格なら60秒でv1.0へ進める。

### v0.8.0 — 書き出しと互換性の完成

**ユーザー成果:** 他の音楽アプリへ安全に持ち出せる。

**実装するもの**

- SMFの読み戻し比較、主要DAW/再生ソフトでの互換性検証。重なった音、連続同音、短音、最大音域を含む。
- 編集済みノートのCSV（秒数/音高/velocity）、編集可能な保存名、出力案内。
- 保存時に「MIDIは音声ではありません」を明示し、試聴音との差を説明。
- **条件付き実験:** 単音録音のピッチベンドを出力し、MIDIチャンネルの制約・DAWの再生・音高可変範囲を検証。曖昧なら機能を非表示にして既定OFFを維持。
- MIDIのテンポ120BPMは時刻をtickへ変換するための固定値であり「推定テンポ」ではないことを記載。

**完了条件**

- MIDIデータが任意の独立パーサーで読めて、画面上のノートのピッチ/時間と一致。
- CSVの時刻・並び・エスケープ・改行が安定。日本語名を付けても保存できる。
- ピッチベンド未搭載でも基本の書き出し品質は落ちない。

測定シートへ必ず記録する項目: 日付、コミットSHA、実行ブラウザ/版、OS/端末、モデル版、サイズ、処理時間、ピークメモリ、検出音符数、参照との誤差、失敗/中止状態。比較対象は同一のテスト音源と設定を使用する。

## 7. 各バージョン共通の実装チェック

- `AGENTS.md`等、現在のテンプレート契約を確認する。実装対象ファイルを先に読む。
- `APP_SPEC.md`、`README.md`、`README.ja.md`、`CHANGELOG.md`、`THIRD_PARTY_NOTICES.md`、UIヘルプの更新を機能に合わせて行う。
- 素材/モデルはnpmバージョン、SHA-256ロック、ライセンスを記録し、必要なものを全て埋め込む。
- PowerShell構文・リポジトリ検証・ビルド・単一HTML静的検証と、少なくとも1つの実操作スモークテストを実施。
- 未処理エラー、音声再生中断、モデルメモリ、Blob URL破棄、入力入替え、無音を回帰確認。
- PC/スマホ、日本語/英語、`file://`、外部通信を確かめ、未実施項目を報告に残す。
- PRを作成/更新できるがマージしない。各段階のDoD達成前に完了と報告しない。

## 8. リスクと回避策

| リスク | 兆候 | 回避策/判定 |
|---|---|---|
| 音声デコードのブラウザ差 | 同じM4Aが片方だけ失敗 | WAV/MP3優先。追加形式はブラウザ依存と説明 |
| TF.jsのTensorメモリリーク | 解析を繰り返すとメモリ増 | 推論資源解放、再利用、反復ストレステスト |
| 配布HTMLが巨大 | 初回起動が遅い | モデル圧縮・不要バンドルの除去、サイズレポート確認 |
| `connect-src 'none'`でモデルが読めない | `fetch(blob:)`などで失敗 | in-memory IOHandler / バイト列からのWASM初期化に変更。CSPを弱めない |
| 音符の誤認識 | 倍音、ノイズ、休止の誤検出 | 感度調整・音域フィルター・手動編集・限界説明 |
| 音声とMIDIの時間ずれ | 休止・音声長に比例した誤差 | 公式の時間補正・独立MIDI再読込・基準音源比較 |
| MIDIピッチベンドの和音問題 | DAWで全ノートが同時に揺れる | 既定OFF。安全条件通過まで提供しない |
| スマホの編集困難 | ノートの端が細く操作できない | 選択ノートの別パネル編集、十分なタップ領域 |
| 保存前データ喪失 | タブ閉鎖・リロード | セッション限定を説明、破棄確認（可能な範囲） |
| 長時間音声のメモリ不足 | 入力直後にタブ再読込 | 初期は60秒。延長はゲート通過後のみ |
