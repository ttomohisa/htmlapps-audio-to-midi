## 1. 記録方法

- テスト項目ごとに `PASS / FAIL / BLOCKED / NOT RUN / N/A`、実行日、コミットSHA、端末/OS/ブラウザ版、使用音源ID、証跡（ログ・画像・動画・出力ファイル）を記録する。
- `A` = 自動化必須または推奨、`M` = 手動確認、`A+M` = 両方。
- 必須項目は、対応バージョン以降すべて回帰対象。モデルの精度結果は「目標と実測」を別列で保管し、未検証を「良好」としない。
- 条件付き機能（5分音源、ピッチベンド）を不採用にした場合は `N/A` とし、UI/ヘルプからも露出を消したことを証跡で確認。

## 3. 品質指標・集計

### 3.1 ノート検出（モデル精度）

モデル精度とMIDIシリアライズ精度を分けて計測する。

- **Note Precision/Recall/F1:** 合成音源と注釈済み実音源に対し、音高一致＋Onset許容誤差（まず±50ms）で対応付け。許容幅は結果と共に記録。
- **Offset誤差:** 合致したノートの終了時刻の絶対誤差を集計。
- **Over-detection:** 入力音にはない余計なノートの発生数。
- **Editing burden:** 目的のメロディーにするまでの手動修正回数と時間。
- 実音源（鼻歌/和音）で**精度100%を要求しない**。改善の方向はベースラインとの比較で判断。

### 3.2 出力の正確性（必須）

- UI内部ノートと再読込したMIDIの音高は完全一致。
- 発音時刻/終了時刻はtickへ丸めた時の誤差を測定し、目標は**20ms以下**。これはモデルの推定精度とは無関係。
- 音符数、重なり、ノートオフ整合、MIDIベロシティ・チャンネルを検証する。

### 3.3 性能（目標値）

- 10/30/60秒のテスト音源を端末ごとに測定。初回（モデル初期化あり）と2回目を分ける。
- 絶対速度SLAは事前に断定しない。ユーザー操作が止まらず、中断/やり直し可能であることを必須条件とする。
- 長時間5分はメモリ・境界・体感の条件を通過した端末/ブラウザのみに公開する。未達なら最大60秒を維持。

## 4. 品質ゲートに対する判定権限

- `PASS`: 実機ログ・ファイル証跡が残り、期待条件を確認済み。
- `FAIL`: 動作に実害がある。v0.9以降、Must機能のFAILを放置して公開しない。
- `BLOCKED`: 環境や機材の不足で未確認。リリース前に代替確認または明示したサポート制限が必要。
- `N/A`: 実装しないと正式に決定した条件付き機能のみ。必須項目の穴埋めには使わない。
