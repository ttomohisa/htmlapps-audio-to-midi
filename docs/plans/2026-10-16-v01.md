# Audio to MIDI v0.1 Implementation Plan

**Goal:** Convert one short local audio file into a valid MIDI file with embedded Spotify Basic Pitch, without runtime networking.
**Architecture:** Preserve the template build/embedded-assets pipeline. Use an isolated CPU worker for inference, pure input/note/MIDI functions, and one generation-owned UI session. Terminating a worker cancels immediately and releases its model and tensors.
**Tech stack:** Browser Web Audio, TensorFlow.js, Spotify Basic Pitch, native Worker, vanilla HTML/CSS/JS, PowerShell release build.
**Spec:** ../../APP_SPEC.md, ../DEVELOPMENT_PLAN.md, ../ACCEPTANCE_MATRIX.md. User-supplied complete design and ten-stage implementation plan are the authority; implement only the first unfinished stage.

## Constraints
- 50 MiB and 0.5–60.0 seconds; average all source channels and resample to 22,050 Hz.
- Standard MIDI File type 1, 480 PPQ, 120 BPM, channel 1, Program 0, fixed velocity 96.
- Model, runtime, worker code and licenses embedded. Keep connect-src 'none'. Never send audio outside the browser.
- Japanese/English; accessible narrow layout, editable filename, cancellable jobs, no automatic audio/note persistence.
- No recording, piano roll, playback or editing in v0.1. No merge or direct main changes.

## Review focus
- Invalid new files must not silently destroy a previous valid result.
- Replacing or cancelling work during decode/model preparation/inference must never revive old output.
- Boundary/NaN notes, same-pitch retriggers and chords must produce correctly ordered finite MIDI events.
- Stereo and resampling must retain timing and use both channels.
- Both offline variants must use the actual model and downloadable MIDI, not mocked inference.

## Tasks
1. Pure processing and MIDI contract (tests first): file/duration validation, mono/resampling, note normalization, generation guard, safe names, MIDI encoder. Independent parser round trips.
2. Runtime technical gate: pinned package/model assets and licenses, local in-memory GraphModel, worker execution/cancellation, deterministic synthetic C4/melody/silence measurements and memory evidence.
3. User flow (tests first): bilingual source/result UI, progress/cancel/reset, input replacement, no-notes/errors, filename/download, help and mobile layout.
4. Release validation: PowerShell preflight/repository build, both variants offline, no network, actual downloaded MIDI readback, documentation and screenshots. Draft PR, exact-head CI and ordinary PR preview QA. Real Windows/Android/iOS device tests remain explicitly unverified if unavailable.
